================================================================================
RUNBOOK: DEPLOYMENT AND OPERATION OF OPENTRACK-ENGINE
================================================================================

This document serves as the definitive technical guide for deploying, configuring,
and maintaining the OpenTrack Engine in laboratory and production environments.

--------------------------------------------------------------------------------
1. PREREQUISITES & ENVIRONMENT VERIFICATION
--------------------------------------------------------------------------------

Before starting, ensure the following services are healthy and reachable:

A. Apache Kafka Cluster:
   - Must be accessible from within the Kubernetes cluster.
   - Default ports in lab: 32001, 32002, 32003.

B. WoT Things Service:
   - Must be reachable at the URL specified in .env.
   - Endpoint example: http://yourip:port

C. Docker Desktop / Kubernetes:
   - Ensure the context is set correctly: `kubectl cluster-info`
   - Image builds must be visible to the K8s node.

--------------------------------------------------------------------------------
2. INITIAL CONFIGURATION (.env)
--------------------------------------------------------------------------------

The `.env` file at the root is the "source of truth". Verify these variables:

   KUBERNETES_NAMESPACE=YourNameSpace
   KAFKA_BROKERS=YourKafkaBrokers
   THINGS_SERVICE_URL=YourThingsService
   WORKER_IMAGE=opentrack-worker:latest

Critical: If using Docker Desktop, use `host.docker.internal` or the specific 
Laboratory IP (192.168.218.12) to ensure connectivity from within containers.

--------------------------------------------------------------------------------
3. KUBERNETES PREPARATION (RBAC)
--------------------------------------------------------------------------------

The API requires permissions to orchestrate Jobs and CronJobs.

1. Create Namespace and apply RBAC:
   $ kubectl apply -f rbac.yaml

2. Verify the ServiceAccount:
   $ kubectl get sa opentrack-api-sa -n api-flow

3. (Optional) Cleanup old resources:
   $ kubectl delete jobs --all -n api-flow
   $ kubectl delete cronjobs --all -n api-flow

--------------------------------------------------------------------------------
4. BUILDING THE WORKER IMAGE
--------------------------------------------------------------------------------

Always rebuild the image after modifying `worker/main.py` or `worker/requirements.txt`.

1. Build without cache to ensure freshness:
   $ docker build --no-cache -t opentrack-worker:latest ./worker

2. Verify image existence:
   $ docker images | grep opentrack-worker

--------------------------------------------------------------------------------
5. RUNNING THE CONTROL PLANE (API)
--------------------------------------------------------------------------------

1. Activate Virtual Environment:
   $ .\venv\Scripts\Activate.ps1  # Windows
   $ source venv/bin/activate     # Linux/Mac

2. Install Requirements:
   $ pip install -r requirements.txt

3. Set PYTHONPATH and Launch:
   $ $env:PYTHONPATH = "."
   $ uvicorn src.main:app --port 8000 --reload

4. Validate API health:
   Navigate to http://localhost:8000/api/v1/automations/ (should return [])

--------------------------------------------------------------------------------
6. OPERATIONAL WORKFLOWS
--------------------------------------------------------------------------------

A. Creating an Automation:
   Use the Swagger UI (http://localhost:8000/docs) to POST a new automation.
   This will immediately create a CronJob in Kubernetes.

B. Triggering Manual Execution:
   If you need to run an inference NOW without waiting for the Cron schedule:
   $ curl -X POST http://localhost:8000/api/v1/automations/{id}/trigger

C. Monitoring Logs:
   To see what a specific worker is doing in real-time:
   $ kubectl logs -n api-flow -f -l app=opentrack-{automation-name}

D. Checking Execution History:
   $ curl http://localhost:8000api/v1/automations/{id}/executions

--------------------------------------------------------------------------------
7. TROUBLESHOOTING (ADVANCED)
--------------------------------------------------------------------------------

Q: Pods stuck in "ImagePullBackOff"?
A: K8s cannot find 'opentrack-worker:latest'. 
   - If using Minikube: `minikube image load opentrack-worker:latest`
   - Ensure `image_pull_policy` is `IfNotPresent` in `src/services/k8s_service.py` 
     if you are not using a remote registry.

Q: KafkaTimeoutError in Worker logs?
A: The worker cannot reach the Kafka brokers.
   - Run a connectivity test from a temporary pod:
     $ kubectl run net-test -it --rm --image=busybox -n api-flow -- nc -zv YourIp 32001
   - Check the "Laboratory Network Hack" in `worker/main.py` to ensure it's 
     pointing to the correct IP.

Q: Automations not appearing in K8s?
A: Check the API console for "K8s Error". Ensure your local Kubeconfig is 
   pointing to the correct cluster (`kubectl config current-context`).

Q: SQLite "Database is locked"?
A: Too many concurrent writes. Restart the API to clear active connections.

--------------------------------------------------------------------------------
8. MAINTENANCE & CLEANUP
--------------------------------------------------------------------------------

To completely reset the system state:
1. Delete all K8s resources: `kubectl delete ns api-flow`
2. Delete the local DB: `rm automations.db`
3. Restart the API.
