# Project Detailed Explanation: OpenTrack Engine

This document provides a deep dive into the internal workings of the OpenTrack Engine system.

## Microservices Architecture

The system is designed to be decoupled and resilient:

1.  **Control Plane (API)**: Manages business logic and persists data in SQLite. It communicates with the Kubernetes API to orchestrate workers.
2.  **Data Plane (Worker)**: Ephemeral containers that run, process data, and are destroyed. This ensures no unnecessary resource consumption.
3.  **Messaging Layer (Kafka)**: Results are sent asynchronously, allowing other systems to consume ML inferences.

---

## Technical Breakdown by File

### Directory: `src/` (The API)

*   **`main.py`**: Configures the FastAPI application and includes support for **CORS**, allowing tools like Swagger UI to work without browser blocks.
*   **`config.py`**: Uses `Pydantic Settings` to centralize configuration. Reads from the `.env` file to adapt Kafka and WoT IPs to the laboratory environment.
*   **`api/v1/automations.py`**: Contains the main logic. When creating an automation, it converts Pydantic models into serializable dictionaries for Kubernetes.
*   **`services/k8s_service.py`**: Manages the Kubernetes lifecycle. It has been optimized with `concurrency_policy="Forbid"` (avoids overlaps) and `backoff_limit=1` (avoids infinite retries).

### Directory: `worker/` (The Worker)

*   **`main.py`**: The Python script that does the heavy lifting:
    *   **Data Collection**: Uses `requests` to read real data from the `things-service`.
    *   **Inference**: Mocks the execution of an ML model with the received data.
    *   **Notification**: Publishes the result to Kafka using the **CloudEvents** standard. A **5-minute timeout** has been configured to support slow or unstable networks.
    *   **Network Patch**: Includes a "hack" to force hostname resolution towards the laboratory IP (`192.168.218.12`), solving external network configuration issues.

---

## Standards Used

*   **Web of Things (WoT)**: For description and access to IoT devices.
*   **CloudEvents v1.0**: To ensure Kafka messages are understandable by any modern system.
*   **RESTful API**: Following FastAPI and OpenAPI best practices.
*   **Kubernetes Native**: Leveraging cloud orchestration capabilities.
